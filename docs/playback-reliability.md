# 播放与连接故障处理

客户端分别显示房间连接状态和本机播放状态。房间断线时，已加载的歌曲可能继续播放；显示“已连接房间”也不代表本机声音一定已恢复。

播放恢复首版已完成静态检查，自动化运行回归与 Windows／Android 真机验收尚待完成。以下说明当前处理方式，不代表已测得的稳定性或后台恢复时限。

## 按提示处理

| 提示或现象 | 建议操作 |
| --- | --- |
| 正在载入、缓冲或尝试恢复 | 等待当前尝试完成；客户端会限制重试次数，不需要连续点击 |
| 这首歌暂时未能载入 | 点击“重试播放”；持续失败时导出诊断交给维护者 |
| 耳机已断开／本机播放已暂停 | 确认输出设备后点击“恢复声音” |
| 需要你点击恢复声音 | 点击恢复入口，允许浏览器启动音频 |
| 音乐源需要服务管理员重新登录 | 联系管理员处理，然后点击“检查状态” |
| 正在连接房间／连接中断 | 等待自动重连，或点击“立即重连”；无需清除身份 |
| 房间身份已失效或房间不存在 | 按页面提示重新加入，必要时向朋友确认房间码 |
| 服务器暂时无法保存操作 | 联系管理员检查磁盘与数据目录；确认房间状态后再操作 |

## 自动恢复会做什么

解析或媒体网络失败会进行有限次数重试；播放地址失效时可重新获取地址。一般故障最多追加两次重试，解码或格式错误最多追加一次，恢复周期受时间预算限制。正常结束、切歌和退出会取消旧任务。

短暂断线使用原身份自动重连，重连后以房间最新状态为准，不补发断线期间的修改命令。若只有当前设备出错，不会因此直接切换全房间歌曲。

耳机断开、通知栏本机静音和系统暂停不会被自动恢复强行解除。“重试播放”不改变音量；“恢复声音”可以恢复记忆音量。恢复后会校准房间进度。

## 导出诊断

播放故障提示中的“导出诊断”由用户主动触发。浏览器请求下载 JSON 文件；桌面或 Android 应用优先复制脱敏文本，复制失败时会显示可手动复制的内容。

诊断只保存在当前进程内，最多 300 条且不超过 256 KiB，不后台上传。内容包含客户端版本、平台类别、状态、故障码和时间等数值；不包含 token、Cookie、服务器地址、播放 URL、房间码、昵称或歌曲名称。

切歌诊断记录请求实际发送（sent）、切歌广播到达（received）的时间和播放版本。请求原因 manual／ended／unplayable 分别表示手动切歌、媒体结束和明确不可播。

Windows 单击“下一首”却跳过一首时，先对照服务端相邻两条“切歌 room=… seq=… track=… reason=… next=…”日志：连续 manual 表示收到了两个有效手动请求；manual 后接 unplayable 表示下一首被复核为不可播；manual 后接 ended 需要继续检查新歌的实际时长和结束事件。

提交问题时可附上诊断、设备与系统版本、问题发生时间，以及当时是否切歌、断网、锁屏或拔出耳机。关闭应用会丢失尚未导出的诊断。

## 服务管理员检查

先确认服务可达，再按 [音乐源配置与管理](PROVIDERS.md) 检查账号和音源状态。解析服务繁忙时会限制并发并返回暂时不可用，不要频繁重启或更换房间身份。

保存失败、服务重启后无法恢复房间等问题见 [部署与运维指南](DEPLOYMENT.md)。保留数据目录和原签名密钥；清空数据或更换密钥会影响原身份恢复。
