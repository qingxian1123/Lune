# Lune Android · UI 升级方案 v2

> **状态:阶段 A / B / C 已全部实施**(U1-U8 + 面板下滑关闭手势 + 页面过渡 + 封面按压反馈,
> 另含房间码收纳改版:顶栏只留品牌字,邀请卡移入成员面板)。阶段 D 未排期。

交互设计稿:`docs/android-ui-v2-proposal.html`(浏览器打开,四屏可切换,右侧注释与升级点一一对应)。

## 一、现状诊断

当前移动端(经三轮迭代)功能完整、布局不再拥挤,但体验上仍有五类可感知的粗糙:

1. **氛围扁平**:取色逻辑移除后,播放页只剩纯黑底 + 静态紫,封面像"贴"在页面上,缺少纵深。
2. **信息盲区**:共听场景的高频疑问「下一首是什么」「现在还连着吗」在界面上无答案——断线时只有人数文字悄悄变化,用户完全无感知。
3. **状态哑巴**:缓冲无任何反馈(上一轮删除文字提示后未补偿);面板打开后 Dock 无高亮,空间感弱。
4. **空态冷清**:未播放时只有灰字占位,新用户进房后不知道第一步该做什么。
5. **动效缺失**:页面切换、面板关闭全是硬切/点按,无手势,不符合 Android 用户直觉。

## 二、设计原则

延续既定方向不动摇:月光暗色系、固定品牌紫(不恢复取色)、无暂停播放模型、
单列信息架构。升级只做**加法中的减法**——每一项都必须回答"用户在哪个瞬间受益"。

## 三、升级建议(八项)

| # | 名称 | 内容 | 用户价值 | 成本 |
| --- | --- | --- | --- | --- |
| U1 | 封面月光辉光 | 封面后置静态品牌紫径向辉光 + 双层投影(暗影+紫晕)+ 1px 内描边 | 找回氛围纵深,零 JS | 纯 CSS |
| U2 | Up-Next 行 | 曲名下方胶囊「接下来 · ○○」,数据取 `queue[0]`,点击打开队列面板 | 高频疑问一眼可见 | 小 |
| U3 | 缓冲反馈 | `isBuffering` 时进度条轨道微脉动动画 | 状态可感知且不占版面 | 纯 CSS + 1 个 class |
| U4 | Dock 高亮态 | 面板打开时对应按钮点亮(`is-active`) | 空间定位感 | 小 |
| U5 | 断线横幅 | `connected === false` 时顶部品牌色细条「正在重连…」带旋转指示 | 断线不再无感 | 小 |
| U6 | 空态升级 | 月牙插画 + 主文案 + 「去搜索一首歌」CTA 直接拉起搜索面板 | 新用户首步引导 | 小 |
| U7 | 歌词页微调 | 上下渐隐遮罩区拉长(18%/78%),滚动进出更柔 | 阅读舒适度 | 纯 CSS |
| U8 | 队列 UP NEXT 徽标 | 队列中第一首待播加徽标,与 U2 呼应 | 队列语义清晰 | 小 |

## 四、动效与手势(阶段 C)

- **面板下滑关闭**:grabber/面板头部区域 touch 下滑超过阈值(~80px)即关闭,跟手位移;
- **页面过渡**:播放页 ↔ 歌词页 220ms 淡入淡出(`opacity` + 轻微 `translateY`);
- **封面按压反馈**:`:active` 时 scale(0.98),提示"可点进歌词";
- 全部遵守 `prefers-reduced-motion`。

## 五、实施计划

| 阶段 | 内容 | 改动面 | 预估 |
| --- | --- | --- | --- |
| A | U1 / U3 / U7:纯样式三件套 | 仅 `mobile.css` | 0.5 天 |
| B | U2 / U4 / U5 / U6 / U8:小功能五件套 | `MobileRoom.tsx` + CSS,无协议改动 | 1 天 |
| C | 手势与过渡动效 | `MobileRoom.tsx`(touch 事件)+ CSS | 1~2 天 |
| D(可选) | 收藏列表页(本地 favorites 落地为可浏览列表)、搜索历史、通知内进度拖动(接 MediaSession seek 回调) | 新组件 / 插件小改 | 按需排期 |

阶段 A + B 合计约 1.5 天即可让整体质感上一个台阶,且全部是前端改动,
热更即可验证,不需要重新出包(阶段 C/D 同理,仅 D 的通知进度拖动涉及插件重编译)。

## 六、明确不做

- 恢复封面取色(已按产品决策移除,静态辉光是其替代);
- 底部 Tab 导航改版(当前 Dock + Sheet 模式已验证可用);
- 亮色主题(月光暗色是品牌本体);
- 播放页常驻队列列表(小屏空间不允许,Up-Next 行已覆盖核心诉求)。
