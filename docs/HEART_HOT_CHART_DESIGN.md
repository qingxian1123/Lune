# Lune 近 7 天爱心热榜方案

> Windows 交互修订：桌面播放条使用透明无边框爱心按钮。服务端确认送心成功后，心形填满；按服务器地址、音乐源和歌曲 ID 在本次客户端进程内记忆，切歌及重新进入房间不清除，关闭并重新打开客户端后恢复空心。不写入本地存储，不支持取消爱心，再次点击仍可送出一颗。键盘导航保留圆形焦点提示。此修订覆盖下文关于 Windows 始终空心、不记录点亮状态的旧描述；Android 保持原有行为。

## 1. 功能目标

为 Lune 增加一个独立的“热榜”页面，根据歌曲最近 7 天收到的爱心数量进行排名，帮助房间成员发现当前服务器近期受欢迎的歌曲。

该功能不是个人收藏：

- 不建立收藏列表。
- 不记录用户是否喜欢过某首歌。
- 不区分设备、用户或房间。
- 不支持取消爱心。
- 爱心次数与播放、加入队列无关。

## 2. 爱心计数规则

每次点击爱心按钮都视为一个独立事件：

- 每点击一次，歌曲爱心总数永久 `+1`。
- 同一个人可以对同一首歌连续发送多颗爱心。
- 不存在取消操作，次数不会减少。
- 加入队列、播放、切歌、搜索和导入歌单均不增加爱心。
- 只有服务端成功接受并保存的爱心才计数。
- 歌曲使用 `provider + trackId` 作为唯一标识。
- 不同音乐源中的同一首歌曲暂不合并。

“永久 `+1`”表示历史总数不回退；热榜排名只汇总最近滚动 168 小时内收到的爱心。

## 3. 爱心按钮设计

现有心形按钮从“收藏开关”改为“送出爱心”动作。

### 3.1 默认状态

- 始终显示空心或线性心形。
- 不显示“已喜欢”状态。
- 不在本地保存点亮状态。
- 提示文案为“送出爱心”。
- 无障碍标签为“为《歌曲名》送出一颗爱心”。

### 3.2 点击反馈

1. 点击后立即产生一次柔和的心形脉冲。
2. 按钮附近短暂出现 `+1`。
3. 服务端确认后完成反馈。
4. 动画结束后恢复默认状态，可以继续点击。

不将爱心永久填满，避免用户将其理解为可以再次点击取消的开关状态。

### 3.3 失败状态

服务端未成功记录时：

- 本次不计数。
- 不显示成功反馈，或撤回尚未完成的 `+1`。
- 提示“爱心没有送出，请重试”。

## 4. 服务端记录方式

每次点击产生一个带唯一请求 ID 的爱心事件：

```ts
{
  requestId: string;
  track: Track;
}
```

请求 ID 只用于避免同一条网络消息被重复处理，不用于识别设备，也不会阻止用户再次点击。

服务端为每首歌曲保存：

| 字段 | 说明 |
| --- | --- |
| `provider` | 音乐源 |
| `trackId` | 音源歌曲 ID |
| `name` | 歌名快照 |
| `artists` | 歌手 |
| `album` | 专辑 |
| `coverUrl` | 封面 |
| `duration` | 时长 |
| `lifetimeHeartCount` | 历史累计爱心 |
| `hourlyHeartCounts` | 最近各小时爱心数 |
| `lastHeartAt` | 最近收到爱心的时间 |

按小时汇总可以避免为每一次点击永久保存独立记录。历史总数永不减少；超过 168 小时的小时统计桶可以清理。

数据保存在当前服务器的 `LUNE_DATA_DIR` 中，服务器重启后继续保留。

## 5. 服务端通信

爱心按钮只出现在房间播放场景中，建议通过现有 WebSocket 发送：

```text
客户端 → send_heart
服务端 → heart_recorded
```

只有服务端持久化成功后才返回确认。

热榜通过 HTTP 查询：

```http
GET /api/charts/hot?window=7d&limit=20&provider=all
```

返回结构：

```ts
{
  window: "7d";
  generatedAt: string;
  tracks: Array<{
    rank: number;
    track: Track;
    heartCount: number;
    lastHeartAt: string;
  }>;
}
```

## 6. 榜单统计与排序

统计范围为当前服务器最近滚动 168 小时。

排序规则：

1. 近 7 天爱心数量降序。
2. 爱心数相同时，最近收到爱心的歌曲优先。
3. 仍相同时，按稳定的歌曲标识排序。

默认展示前 20 首，接口最多允许读取前 50 首。

不同 Lune 服务器各自维护榜单，不创建跨服务器总榜。

## 7. 客户端信息结构

“选歌”界面保持三个同级标签：

```text
┌────────┬────────┬────────┐
│  搜歌  │  歌单  │  热榜  │
└────────┴────────┴────────┘
```

### 7.1 搜歌

关键词搜索单曲，作为默认标签。

### 7.2 歌单

关键词搜索歌单，支持查看曲目和整单加入。

### 7.3 热榜

展示当前服务器最近 7 天收到爱心最多的歌曲。

三个标签共享音乐源筛选器，并分别保留自己的搜索结果和滚动位置。桌面侧栏与 Android 底部面板采用相同结构。

## 8. 热榜列表

页面标题：

```text
近 7 天热榜
按最近 168 小时收到的爱心排序
```

每行展示：

- 排名。
- 专辑封面。
- 歌名与歌手。
- 音乐源。
- 近 7 天爱心数。
- “加入”按钮。

示意：

```text
01  [封面]  歌名
            歌手 · 网易云        ♥ 1,284    [加入]
```

前三名使用不同强度的薰衣月光突出，不使用金银铜奖牌。点击“加入”只操作播放队列，不增加爱心数。

## 9. 榜单状态

### 9.1 加载

> 正在读取近 7 天热度

### 9.2 空榜

> 近 7 天还没有收到爱心  
> 播放一首歌，送出这里的第一颗心吧

### 9.3 加载失败

> 热榜暂时无法载入  
> 请检查服务器连接后重试

提供“重新载入”按钮，不影响搜歌和歌单。

### 9.4 刷新

热榜在以下时机更新：

- 首次进入热榜。
- 再次进入且缓存已经过期。
- 用户主动刷新。
- 音乐源筛选发生变化。
- 服务器地址发生变化。

不实时调整正在浏览的榜单，避免用户点击爱心时列表不断跳动。

## 10. 重复点击与稳定性保护

产品明确允许重复送出爱心，因此用户可以连续点击影响排名。

系统只进行基础稳定性保护：

- 限制异常高频的网络请求。
- 使用请求 ID 防止同一消息因网络重传被重复处理。
- 限制请求体大小和歌曲字段长度。

这些保护不用于识别设备或限制正常重复点击。

## 11. 功能边界

本期不包含：

- 个人收藏与收藏列表。
- 点亮或取消点亮状态。
- 设备或用户去重。
- 每人每天次数限制。
- 加入队列热度。
- 播放次数统计。
- 排名升降趋势。
- 日榜、月榜和历史总榜页面。
- 不同音乐源的同曲合并。
- 跨服务器排行榜。
- 实时榜单跳动更新。

## 实现与验证

桌面播放条与移动播放页复用 `HeartButton`，通过 `useHearts` 发送 `send_heart`（`requestId` 与 `track`）。服务端写入成功后返回 `heart_recorded`，失败返回 `heart_failed`；点击立即产生脉冲，只有收到成功确认才显示 `+1`。按钮不读取或写入本地收藏状态，允许再次送心。Android 系统媒体操作中沿用的 `favorite` 动作也已映射为送出爱心。

`ChartsModule` 提供 `GET /api/charts/hot?window=7d&limit=20&provider=all`，仅支持 `7d`，默认 20 首、最多 50 首，可按音乐源筛选。`HeartStore` 将数据保存为 `LUNE_DATA_DIR/hearts.json`；未设置目录时使用服务端进程工作目录下的 `data/hearts.json`。同一数据目录要求单个写入进程，进程内写入串行化，通过临时文件写入、同步与重命名持久化，成功后才发布内存状态与确认。

小时桶内保存精确时间戳与次数明细，查询按 `(当前时间 − 168 小时, 当前时间]` 汇总，因此不足整小时的窗口边界也准确。历史累计数保留，过期明细在后续写入时清理；请求 ID 去重记录覆盖 168 小时并持久化，清理同样在写入时进行。

`HotChartPanel` 在选歌区与搜歌、歌单并列，缓存按服务器地址和音乐源区分，60 秒后视为过期。首次进入、过期后再次进入或切换到缺少新鲜缓存的查询时读取榜单，也可手动刷新；不因窗口聚焦、网络恢复或送心实时重排。列表沿用深色平面与薰衣月光，前三名仅提高排名文字强调，移动端加入按钮保留至少 44px 的触控高度。

在仓库根目录执行以下验证命令：

```sh
pnpm --filter @lune/server test:hearts
pnpm typecheck
pnpm build
```

这些命令分别用于爱心服务端测试、类型检查与工作区构建，不代表已完成 Android 原生 APK 或真机验证。
